# Release Builder — 构建发布

## 职责

处理代码审查通过后的构建、版本管理、发布和上线收尾工作。

## 触发场景

- Code Review 通过后准备发布
- 用户说"发布"、"构建"、"上线"、"release"

## 工作流程

### Step 1: 构建验证
1. 运行项目构建命令，验证构建成功
2. 确认没有构建警告或错误
3. 如果构建失败，分析原因并报告

### Step 2: 发布选项
向用户展示发布选项：

| 选项 | 适用场景 |
|------|----------|
| 创建 Pull Request | 需要合并到主分支 |
| 直接合并 | 简单项目或独立分支 |
| 打 Tag 发布 | 需要版本标记 |
| 打包部署 | 需要部署到服务器 |

### Step 3: 执行发布
根据用户选择的选项执行发布操作。

### Step 4: 清理收尾
- 删除已合并的本地分支（如适用）
- 确保工作区干净
- 记录发布信息

## 输出
- 构建成功/失败报告
- 发布记录（版本号、时间、变更内容）
- 项目状态更新
